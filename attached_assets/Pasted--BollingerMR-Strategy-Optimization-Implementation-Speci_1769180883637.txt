## PHASE 0: Foundation Fixes (Implement Immediately)
 
### 0.1 Fix: calcBBWidthPercentile() Helper in utils.ts
 
**Location:** `forex-decision-engine/src/strategies/utils.ts`
 
**Critical Requirements:**
1. Define BBand type LOCALLY in utils.ts (do NOT import from SignalQualityGate)
2. Use Number.isFinite() for ALL numeric checks (NOT truthy checks)
3. Exclude current bar from percentile calculation (history only)
4. Return null for insufficient data
 
**Type Definition (add to utils.ts):**
```
Interface BBand with properties:
- upper: number
- middle: number
- lower: number
```
 
**Function Specification:**
```
Function: calcBBWidthPercentile
Parameters:
- bbands: BBand[] (array of Bollinger Band values)
- currentIdx: number (index of current bar)
- lookback: number = 50 (default)
 
Returns: { width: number, percentile: number } | null
 
Logic:
1. Return null if bbands invalid, currentIdx < 0, or bbands[currentIdx] missing
2. Validate current BB using Number.isFinite() for upper, lower, middle
3. Validate middle !== 0
4. Calculate width = (upper - lower) / middle
5. Return null if width is not finite or width <= 0
6. Loop from startIdx (max of 0 or currentIdx - lookback) to currentIdx - 1 (EXCLUDE current)
7. For each bar, validate with Number.isFinite() before adding to widths array
8. Return null if widths.length < 10 (minimum history)
9. Sort widths, calculate rank of current width, return percentile
```
 
### 0.2 Fix: Rejection Candle as HARD GATE in BollingerMR.ts
 
**Location:** `forex-decision-engine/src/strategies/intraday/BollingerMR.ts`
 
**Current Behavior (WRONG):**
- BB touch gives +25 confidence
- Rejection candle gives +20 bonus (optional)
- Trade can pass without rejection
 
**Required Behavior (CORRECT):**
- Check rejection FIRST
- If rejection.ok === false, return null immediately (hard gate)
- If rejection passes, then proceed with confidence scoring
- Combined confidence for touch + rejection = 40 points
 
**Logic for LONG setup:**
```
1. Check if signalBar.low <= bbSignal.lower
2. IMMEDIATELY check: rejection = isRejectionCandle(signalBar, 'long')
3. IF !rejection.ok: return null  // HARD GATE
4. THEN set direction = 'long'
5. Add confidence += 40 (combined touch + rejection)
6. Add trigger message including wick percentage
7. Check RSI < 30 (TIGHTENED from 35) for bonus
```
 
**Logic for SHORT setup:**
```
1. Check if signalBar.high >= bbSignal.upper
2. IMMEDIATELY check: rejection = isRejectionCandle(signalBar, 'short')
3. IF !rejection.ok: return null  // HARD GATE
4. THEN set direction = 'short'
5. Add confidence += 40
6. Check RSI > 70 (TIGHTENED from 65) for bonus
```
 
### 0.3 Fix: BB Width Expansion Filter in BollingerMR.ts
 
**Location:** After BB validation, before signal logic
 
**Import Required:** calcBBWidthPercentile from '../utils.js'
 
**Logic:**
```
1. Call calcBBWidthPercentile(bbands, signalIdx, 50)
2. If result exists AND result.percentile > 80:
   return null  // Expansion regime - don't fade
```
 
**Rationale:** When BB width is in top 20th percentile (expanding), touches are likely continuations, not reversals.
 
### 0.4 Fix: Stop Loss Methodology (Setup-Invalidation Stop)
 
**Location:** Replace existing stop calculation in BollingerMR.ts
 
**Current (WRONG):**
```
stopLossPrice = entryPrice - (atrSignal * 1.5)  // Pure ATR
```
 
**Required (CORRECT) - 2-Bar Setup-Invalidation:**
```
For LONG:
1. Get prevBar = bars[signalIdx - 1]
2. recentLow = min(signalBar.low, prevBar.low) with fallback
3. stopLossPrice = recentLow - (atrSignal * 0.4)  // 0.4 ATR buffer
 
For SHORT:
1. Get prevBar = bars[signalIdx - 1]
2. recentHigh = max(signalBar.high, prevBar.high) with fallback
3. stopLossPrice = recentHigh + (atrSignal * 0.4)
```
 
**Buffer Value:** Start with 0.4 ATR (middle of test range). This will be validated in Phase 1.
 
**Code Comment Required:**
```
// SETUP-INVALIDATION STOP: Not a swing stop or liquidity-aware stop.
// If price breaks the immediate extreme of the rejection setup,
// the reversal thesis is invalidated. Buffer = 0.4 ATR (Phase 1 baseline).
```
 
### 0.5 Fix: Take Profit Configuration
 
**Current:**
```

**Required:**

```
 
**Rationale:** Mean-reversion benefits from hitting targets. Keeping ATR fallback at 1.5 prevents over-stretching.

### Specification (For Future Reference)
 
**Cluster Detection Parameters:**
- Lookback: 20 bars (excluding signal bar and entry bar)
- Zone width: 0.15 ATR (clamped between 5-30 pips for FX)
- Touch threshold: 2+ touches
- Touch definition: Wick enters zone AND close >= level - 0.05 ATR
 
**Buffer Escalation:**
- Default: 0.4 ATR (from Phase 1)
- Escalated: 0.5 ATR (when cluster detected)
