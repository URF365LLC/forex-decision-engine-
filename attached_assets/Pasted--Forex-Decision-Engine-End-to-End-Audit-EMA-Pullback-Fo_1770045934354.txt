# Forex Decision Engine — End-to-End Audit (EMA Pullback Focus)

**Date:** 2026-02-01  
**Scope:** Full codebase audit with priority focus on EMA Pullback false-signal root causes.  
**Method:** File-by-file review of first‑party code, inventory of third‑party dependencies, and deep trace of data → indicators → strategy → gating → API → UI.

---

## 1) Executive Summary (1–2 pages)

### Most likely root causes of false EMA Pullback signals (ranked)

**P0 — Timeframe wiring mismatch: EMA200 + ADX are Daily, but EMA Pullback uses them as H1 inputs.**  
The indicator service fetches **EMA200 and ADX from `daily` bars** and then pads them to match the **H1 entry bars**. The EMA Pullback strategy then uses these daily values as if they were **H1 EMA200 and H1 ADX**, which can invert trend direction, distort pullback zone logic, and over/under‑gate trades. This is the single most direct, code-proven cause of false signals.

**P0 — Timestamp ambiguity (no timezone) → bar-closure & cache fingerprint errors.**  
Market data timestamps from Twelve Data are stored as strings without timezone. Every closed‑bar and freshness gate relies on `new Date(timestamp)` without enforcing UTC. If the timestamp is local‑interpreted (or if Twelve Data returns local exchange time), bars can be marked **closed when they are still open**, or **stale when they are fresh**, leading to partial‑bar usage and incorrect cache invalidation.

**P1 — Entry indicator alignment uses padding rather than timestamp matching.**  
Entry indicators (EMA20/EMA50/RSI/ATR/etc.) are **not timestamp‑aligned to H1 bars**. Instead, shorter arrays are padded with `NaN` at the front, assuming the last N values match the last N bars. If the indicator API omits the latest bar or drops a timestamp, this creates an **off‑by‑one/offset** where indicators correspond to the wrong bar.

**P1 — Missing data treated as `0`, which passes validity checks.**  
`parseFloat(v.value || '0')` silently converts missing OHLCV/indicator values into **0**, which is considered “valid”. EMA/ADX of `0` can trigger or block signals incorrectly, and zeroed OHLCV can distort ATR and candles.

**P1 — Cache TTL can serve stale bars around candle rollover.**  
Entry bars and indicators are cached for **5 minutes**. A new H1 bar close can occur while cached data still holds the prior bar. This is particularly risky at the top of the hour, when EMA Pullback expects the just‑closed bar for signal evaluation.

**P2 — Manual vs Auto settings mismatch (timezone/paperTrading/equity dropped).**  
The settings validator keeps only `{ accountSize, riskPercent, style }`, silently discarding `timezone`, `paperTrading`, and `equity`. This creates UI/Backend contract drift, and can subtly alter validity windows and risk gating.

### P0 / P1 / P2 Issue Summary

| Priority | Issue | Why it matters for EMA Pullback |
|---|---|---|
| **P0** | Daily EMA200 + ADX used as H1 inputs | Core trend and ADX gates are using the wrong timeframe. This directly flips signal logic. |
| **P0** | Timestamp timezone ambiguity | Closed‑bar checks and cache fingerprints can be wrong → partial bar usage. |
| **P1** | No timestamp alignment for entry indicators | Off‑by‑one alignment yields false signals. |
| **P1** | Missing data coerced to 0 | Indicators become valid zeros, skewing all gating. |
| **P1** | 5‑min cache TTL around bar close | stale data → false EMA pullback triggers. |
| **P2** | Settings validation strips fields | UI values differ from back‑end usage (timezone, paper vs live). |

---

### “If we fix only 3 things, fix these”

1. **Rewire EMA200 + ADX to use H1 (entry) timeframe** for EMA Pullback, or explicitly rename and update the strategy to use Daily EMA/ADX as designed.  
2. **Normalize timestamps to UTC** (append `Z` or parse with timezone) so bar-closure + freshness checks operate on the correct clock.  
3. **Align entry indicators to bars by timestamp**, not by padding length.

---

### Risk statement: production impact

The combination of **timeframe mismatch** and **timestamp ambiguity** can cause EMA Pullback signals to appear when the local H1 EMA/ADX would never allow them. In live use, this can manifest as **false long signals during downtrends** (or vice‑versa) and **signals appearing early on partial bars**. The risk is high for intraday automation and moderate for manual scanning.

## 3) Deep Dive: EMA Pullback Strategy Trace

### A) End‑to‑End Data Pipeline Trace (EMA Pullback path)

1. **Market Data Source** → Twelve Data API (`/time_series`, `/ema`, `/adx`, `/atr`, etc.).
2. **Ingestion** → `twelveDataClient` fetches OHLCV and indicators.
3. **Normalization** → `parseFloat` on OHLCV/indicator strings, timestamps stored as `v.datetime` string.
4. **Storage/Cache** → In‑memory cache with TTL (5 min H1, 4 hr D1). 
5. **Indicator Calc** → Uses Twelve Data indicator APIs (EMA/ADX/ATR/RSI). 
6. **Strategy Calc** → `strategyAnalyzer` converts indicator data into strategy format (padding to bar length). 
7. **Signal Gate** → `SignalQualityGate.runPreFlight` + EMA Pullback gates. 
8. **Signal Output** → `buildDecision` builds normalized decision object. 
9. **API** → `/api/scan` returns decisions to UI. 
10. **UI Display** → `public/js/app.js` renders decision and signal history. 
11. **Journal/History** → Signals are stored via `signalStore` (auto scan) and `journalStore` (manual trade tracking).

### B) EMA Pullback path: Imports → Calls → Transformations → Outputs

**Key flow:**

1. **`/api/scan`** (server) → `scanWithStrategy`  
2. **`scanWithStrategy`** → `analyzeWithStrategy`  
3. **`analyzeWithStrategy`** → `getIndicators`  
4. **`getIndicators`** → `fetchIndicators`  
5. **`fetchIndicators`** → `twelveData.getOHLCV`, `getEMA`, `getADX`, etc.  
6. **`fetchIndicators`** returns **entryBars (H1)** + **ema20/ema50/rsi/atr** (H1) + **ema200/adx (Daily)** + **H4 trend pack**.  
7. **`convertToStrategyIndicatorData`** pads indicator arrays to match H1 bar length.  
8. **EMA Pullback `analyze`** uses `ema200`, `adx`, `ema20`, `ema50`, `atr`, `rsi` to gate and score.
9. **`buildDecision`** constructs entry/SL/TP, risk, timing. 
10. **Decision** returned through `/api/scan` to UI.

### C) Critical Observations for EMA Pullback

- **EMA200 + ADX are fetched from Daily bars** but used for **H1 gates** (trend + ADX min gate).  
- **Entry bar timestamps** are used to determine closed‑bar status; timezone ambiguity can misclassify bar closure.  
- **Indicator arrays** are padded to bar length without timestamp alignment, risking offset errors.

## 4) Data Integrity Findings (Proof‑Based)

### Issue DI‑1 (P0): Daily EMA200 + ADX used as H1 inputs

- **Symptom:** EMA Pullback sees trend alignment where H1 EMA200/ADX would disagree; signals appear during H1 counter‑trend moves.  
- **Root Cause:** `fetchIndicators` requests `EMA200` and `ADX` from the **daily** interval, then `convertToStrategyIndicatorData` pads them to H1 bars. EMA Pullback uses `ema200` and `adx` as if they are H1 values.  
- **Proof:** 
  - `fetchIndicators` uses `twelveData.getEMA(symbol, 'daily', ...)` and `getADX(symbol, 'daily', ...)`.  
  - `convertToStrategyIndicatorData` pads and assigns `ema200`/`adx` to H1 bar arrays.  
  - EMA Pullback gate 3 uses `adxSignal` as **H1 ADX**; trend gates use `ema200Signal` as **H1 EMA200**.
- **Impact:** High false‑signal risk for EMA Pullback (trend gating and EMA zone checks are using daily trend).  
- **Fix:** 
  - Either compute **H1 EMA200 + H1 ADX** (preferred), or rename `ema200`/`adx` to `ema200D1`/`adxD1` and update EMA Pullback to explicitly use `ema200H1`/`adxH1` or H4 trend only.

---

### Issue DI‑2 (P0): Timestamp ambiguity leads to partial‑bar usage

- **Symptom:** Signals appear before the H1 bar closes; cache fingerprint can use wrong “last closed bar”.  
- **Root Cause:** Timestamps from Twelve Data (`v.datetime`) are stored without timezone and parsed via `new Date(timestamp)`. `SignalQualityGate.checkBarClosure` and `strategyAnalyzer.getLastClosedBar` rely on that parsing for closure logic.  
- **Proof:** `getOHLCV` stores raw `datetime` strings as `timestamp`. `checkBarClosure` and `getLastClosedBar` parse them without forcing UTC.  
- **Impact:** H1 and H4 closure rules can be misapplied. Partial bars can slip through gates, corrupting EMA Pullback signals.  
- **Fix:** Normalize timestamps to UTC (e.g., append `Z` if missing, or parse in known exchange timezone and convert to ISO).

---

### Issue DI‑3 (P1): Entry indicator alignment uses padding, not timestamp matching

- **Symptom:** EMA/RSI/ADX appear offset by 1+ bars, producing pullbacks that don’t exist in actual data.  
- **Root Cause:** Entry indicators are padded to match bar length without matching by timestamp. Any missing/latest bar in indicator arrays shifts alignment.  
- **Proof:** `convertToStrategyIndicatorData` uses `padIndicatorToBarsLength` (front‑padding), not timestamp alignment.  
- **Impact:** High risk of H1 EMA/ADX/RSI misalignment causing false signals.  
- **Fix:** Align entry indicators to bars by timestamp (same as `alignIndicatorToBars` does for H4/D1), and leave missing bars as NaN.

---

### Issue DI‑4 (P1): Missing OHLCV/indicator values are coerced to 0

- **Symptom:** Spikes in 0-valued EMA/ADX/price create false gates.  
- **Root Cause:** `parseFloat(v.value || '0')` converts missing data to `0`, which passes numeric validity checks.  
- **Proof:** `getOHLCV` and `getIndicator` use `parseFloat(... || '0')`.  
- **Impact:** False signals or missing rejection conditions when the API returns blank/missing values.  
- **Fix:** Use `NaN` for missing values, and enforce `Number.isFinite` checks before signal logic.

---

### Issue DI‑5 (P1): H1 cache TTL can serve stale candles

- **Symptom:** After a new hour closes, EMA Pullback may still evaluate on the prior bar for up to 5 minutes.  
- **Root Cause:** H1 OHLCV and indicators are cached for 5 minutes. The cache key does not include `lastClosedBar`.  
- **Proof:** `CACHE_TTL.H1` is 5 min; indicator bundle uses TTL 5 min and does not incorporate bar timestamps.  
- **Impact:** Stale data causes false signals around bar boundaries.  
- **Fix:** Fingerprint indicator cache with last closed bar timestamp (similar to decision cache), or reduce TTL to <= 1 minute.

---

### Issue DI‑6 (P2): Settings validation strips fields used by UI/strategy

- **Symptom:** UI‑selected timezone, paperTrading, equity are ignored; validity windows and drawdown gating are inconsistent.  
- **Root Cause:** `validateSettings` sanitizes only `{ accountSize, riskPercent, style }`.  
- **Proof:** `validateSettings` returns only those fields; `/api/scan` uses sanitized settings.  
- **Impact:** UI↔backend mismatch and unexpected behavior; not primary source of EMA false signals but increases drift risk.  
- **Fix:** Extend validator to include required fields and update Zod schema accordingly.

### Phase 1 — Correctness Fixes (Data Alignment + Indicator Math)

   - Files: `src/engine/indicatorService.ts`, `src/strategies/intraday/EmaPullback.ts`  
   - Sketch:
     ```ts
     // Add H1 EMA200/ADX fetch
     const ema200H1 = await twelveData.getEMA(symbol, entryInterval, 200);
     const adxH1 = await twelveData.getADX(symbol, entryInterval, 14);
     // Use ema200H1/adxH1 for EMA Pullback gates.
     ```
   - Tests: Unit test for indicator bundle includes H1 EMA200/ADX in correct lengths.
   - Acceptance: EMA Pullback uses H1 EMA200/ADX (confirm by log snapshots).

2. **Timestamp normalization** (UTC enforcement).  
   - Files: `src/services/twelveDataClient.ts`, `src/strategies/SignalQualityGate.ts`, `src/engine/strategyAnalyzer.ts`  
   - Sketch:
     ```ts
     function normalizeTimestamp(ts: string): string {
       return ts.endsWith('Z') ? ts : `${ts}Z`;
     }
     ```
   - Tests: Unit test ensures `normalizeTimestamp('2026-01-01 00:00:00')` is parsed in UTC.
   - Acceptance: closed‑bar checks behave correctly when system timezone ≠ UTC.

3. **Timestamp alignment for entry indicators.**  
   - Files: `src/engine/indicatorService.ts`, `src/engine/strategyAnalyzer.ts`  
   - Sketch:
     ```ts
     const ema20Aligned = alignIndicatorToBars(entryBars, ema20Raw, 'H1 EMA20');
     ```
   - Tests: Integration test with deliberately missing indicator bar ensures NaNs align to missing timestamps.
   - Acceptance: no off‑by‑one offsets in EMA Pullback signals.

### Phase 2 — Parity & Cache Hardening

1. **Indicator cache fingerprinting using last closed bar.**  
   - Files: `src/services/cache.ts`, `src/engine/indicatorService.ts`  
   - Acceptance: cache keys vary by bar close; indicator data updates immediately on new bar.

2. **Manual vs Auto parity** (settings pass‑through).  
   - Files: `src/utils/validation.ts`, `src/validation/schemas.ts`, `src/server.ts`  
   - Acceptance: timezone/equity/paperTrading survive validation and are honored in strategy + drawdown checks.

### Phase 3 — Observability + Regression Prevention

1. **Add EMA Pullback telemetry** (bar timestamps, indicator alignment status, strategy gates).  
   - Files: `src/strategies/intraday/EmaPullback.ts`  
   - Acceptance: debug logs show indicator timestamps and gating outcomes in production.

2. **Test harness for synthetic bars** (EMA Pullback).  
   - Files: `src/engine/indicatorService.ts` test utilities, new test file.

## 6) Verification Protocol (Reproducible)

### A) Reproduce false EMA Pullback signal

1. Pull H1 OHLCV for a known pair where daily EMA200 is far from H1 EMA200 (e.g., after trend reversal).  
2. Run EMA Pullback with current code.  
3. Compare with H1 EMA200 computed locally.  
4. If the system shows a signal where local H1 EMA200 disqualifies it, the bug is confirmed.

### B) Synthetic candle sequences

Create a synthetic sequence where:
- H1 EMA200 is above price (bearish), but daily EMA200 is below price (bullish).  
- The system should **not** produce long signals if using H1 EMA200.  
- Validate that the current code produces a long signal (false).  

### C) Bar alignment and last‑bar handling

1. Inject a missing indicator value in the last bar (simulate API lag).  
2. Verify that the strategy does **not** trade on this bar.  
3. Verify that the timestamp‑aligned logic leaves NaN and skips trade.

### D) Logging/metrics checks

Add debug counters for:
- `lastClosedBarTs` used in cache keys.  
- Indicator alignment match rate (H1 EMA20/EMA50).  
- Gate rejections in EMA Pullback.
