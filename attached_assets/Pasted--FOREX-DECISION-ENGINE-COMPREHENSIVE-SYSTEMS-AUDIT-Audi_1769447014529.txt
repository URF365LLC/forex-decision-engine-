### Finding #2: Memory Leak in journalStore.ts (P0)
 
**Symptom:** `persistSync()` method references `this.nextId` which is undefined in certain code paths.
 
**Evidence:** `src/storage/journalStore.ts:762`
```typescript
// Line 762 in persistSync()
fs.writeFileSync(tempPath, JSON.stringify({
  entries: this.entries,
  nextId: this.nextId,  // <-- this.nextId may be undefined
}, null, 2));
```
 
The `JournalStore` class initializes `nextId` in `load()` but if the file doesn't exist and an exception occurs, `nextId` remains undefined.
 
**Root Cause:** Initialization logic doesn't guarantee `nextId` is set before use.
 
**Impact:**
- JSON serialization could fail or produce `{"nextId": undefined}`
- Journal data corruption risk
- Server crash on shutdown
 
**Proposed Fix:**
```typescript
class JournalStore {
  private nextId: number = 1;  // Initialize with default
 
  constructor() {
    this.load();  // load() can override
  }
}
```

### Finding #3: Cache Key Missing Strategy Version (P1)
 
**Symptom:** Strategy changes don't invalidate cached analysis results.
 
**Evidence:** `src/engine/strategyAnalyzer.ts:145-155`
```typescript
const cacheKey = cache.makeKey(
  symbol,
  entry.timeframe,
  'strategy-result',
  { strategyId, style: settings.style },
  fingerprint  // Based on bar timestamp, NOT strategy version
);
```
 
**Root Cause:** Cache key construction doesn't include strategy version string.
 
**Impact:**
- After deploying a strategy fix, old (buggy) results may still be served
- Version `2026-01-23` BollingerMR changes won't take effect until cache expires
 
**Proposed Fix:**
```typescript
const strategyMeta = strategyRegistry.getMeta(strategyId);
const cacheKey = cache.makeKey(
  symbol,
  entry.timeframe,
  'strategy-result',
  {
    strategyId,
    style: settings.style,
    version: strategyMeta?.version || 'unknown'  // <-- Add version
  },
  fingerprint
);
```

### Finding #4: No Database Transactions (P1)
 
**Symptom:** Multi-table operations lack atomicity.
 
**Evidence:** `src/storage/detectionStore.ts:58-136` (createDetection)
```typescript
export async function createDetection(input: CreateDetectionInput): Promise<DetectedTrade> {
  // Creates detection object
  const detection = { ... };
 
  // Inserts to DB (no transaction)
  await db.insertInto('detections').values({...}).execute();
 
  // If this fails, detection object is returned but DB is inconsistent
  return detection;
}
```
 
**Root Cause:** Kysely transaction API not utilized.
 
**Impact:**
- Partial writes on concurrent operations
- Orphaned records possible
- Data integrity issues under load
 
**Proposed Fix:**
```typescript
export async function createDetection(input: CreateDetectionInput): Promise<DetectedTrade> {
  const db = getDb();
 
  return await db.transaction().execute(async (trx) => {
    const detection = { ... };
    await trx.insertInto('detections').values({...}).execute();
    return detection;
  });
}
```

### Finding #5: Frontend Global State Race Conditions (P1)
 
**Symptom:** Multiple async operations can corrupt shared state.
 
**Evidence:** `public/js/app.js:45-60`
```javascript
let state = {
  decisions: [],
  isScanning: false,
  autoScan: { isRunning: false },
  // ... more mutable global state
};
 
// Multiple concurrent calls can interleave
async function fetchDetections() {
  state.isLoading = true;  // Race condition
  const data = await api.getDetections();
  state.decisions = data;  // Another call may overwrite
  state.isLoading = false;
}
```
 
**Root Cause:** No state management library or mutex pattern.
 
**Impact:**
- UI shows stale/inconsistent data
- "Flash of old content" issues
- Hard-to-reproduce bugs
 
**Proposed Fix:**
- Implement simple state machine pattern
- Or migrate to lightweight framework (Preact/Alpine.js)
