2) Order Blocks — Best Integration Point (Entry & Stop Refinement)
What the module provides
The Order Block module identifies bullish/bearish order blocks, scores them (weak/moderate/strong), and filters out “mitigated” blocks. It also provides a helper to find the nearest OB relative to price, and a check to see if price is inside the block.

Recommended integration stage
After sweep direction is determined, before entry/stop is finalized, because you already know direction and have SMC bars ready. This lets you:

Prefer entries inside a valid OB in the same direction.

Tighten the stop to the OB boundary rather than the sweep extreme.

Adjust confidence based on OB strength.

Why this is compatible with current flow
The strategy already builds smcBars, and OB detection uses only bar data + internal ATR (computed inside the module). No new indicators or pipeline changes required.

Direction is already decided right after sweep detection, which is the correct moment to fetch OBs for that direction.

Specific integration effects (no code)
Entry refinement: If the entry bar price is inside a strong/moderate OB, treat as “preferred entry zone.”

Stop refinement: Use OB low/high for stop buffer instead of sweep extreme.

Confidence boost: Tie to OB strength (strong/moderate/weak), which is already computed by the module.

3) Fair Value Gaps — Best Integration Point (Targets / TP Structure)
What the module provides
The FVG module detects bullish/bearish gaps, tracks fill %, and filters out filled gaps. It also provides a helper to find the nearest unfilled FVG relative to price and direction.

Recommended integration stage
After risk is computed and before take‑profit is finalized.
This is where the strategy currently checks opposing liquidity zones and then falls back to fixed RR targets.

Why this is compatible with current flow
FVG detection uses only bar data and internal config.

Direction is already known.

The strategy currently only chooses one take‑profit level; this is the natural place to replace or augment that logic with FVG‑based targets.

Specific integration effects (no code)
Primary target: nearest unfilled FVG in trade direction.

Fallback: if no FVG found, keep the existing opposing‑liquidity / RR target logic.

Tiered exits: if you want to maintain multiple targets, the buildDecision call already accepts a takeProfitConfig that can be extended for tiered logic later (it currently supports structure/ATR/RR).

4) Confluence Logic (OB + FVG Overlap)
Why this is valuable
The most robust Smart Money entries happen when order blocks and FVGs overlap (institutional zone + imbalance).

Overlap exists if ranges intersect.

Effects

More selective trade filtering (optional – can be a scoring boost rather than a hard requirement).

Both modules already expose the properties needed for overlap detection: low, high, midpoint.

6) Integration Risks / Considerations
Signal Frequency Reduction
Using OB/FVG as hard filters will reduce signals; using them as confidence boosts preserves volume. Decide which behavior you want based on expected trade frequency.

Stop‑Loss Tightening Risk
Using OB boundaries for stops can improve RR but may increase stop‑outs in choppy conditions. Consider using an ATR buffer around the OB boundary.

FVG Target Distance
Some FVGs may be too close (sub‑RR targets). You may want a minimum RR threshold before using a gap as a target, and fall back to liquidity zones if that threshold is not met.
